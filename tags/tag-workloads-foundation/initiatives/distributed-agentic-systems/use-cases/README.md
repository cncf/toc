# Use cases

Worked examples of distributed agent systems running on Kubernetes, written up by the people who run them. Each one shows which patterns in the document a real system uses, which decisions its team made and why, and where the standards or the document fall short.

Use cases are evidence for the reference architecture (chapter 07) and the gap analysis (chapter 08). The architecture names component roles and decision points; a use case shows one real choice at each point.

## Adding one

Copy [TEMPLATE.md](./TEMPLATE.md) to a new file named after the system, for example `docs-agent.md`, fill it in, and open a pull request. Keep it short; one to two pages is enough. Link to code and docs rather than reproducing them.

Rules from the terms of reference apply: a use case can name the projects and products it runs on, but the document's patterns are never based on a single project.
